# ぴょんぴょんゲーム

こたえをタップすると跳んで、障害物を越えられる。子ども（5〜8歳）向けの足し算ランナーです。
iPhone / iPad の Safari で動く PWA として作っています。App Store も開発者登録も不要で、
ホーム画面に追加すればアプリのように全画面で遊べます。

企画・設計プラン: https://claude.ai/code/artifact/c5b62188-3d3a-4597-930a-6a03c314541a

---

## あそびかた

1. 画面の上に式が出る（例: `7 + 5 = ?`）
2. 下のボタンから答えをタップする
3. 正解するとキャラが跳んで、障害物が足元を通り抜ける
4. 10問目は「ラスト 1もん」。障害物がひとまわり大きくなり、低い音が鳴る
5. その1問を当てると **フィニッシュ**。えらんだ ぶきで大げさに相手を倒して ＋20コイン
   （途中でやめると見られない → [フィニッシュ](#フィニッシュ最後までやりきる理由)）
6. まちがえた式があれば、そのあと**リベンジ**。ぜんぶ正解するとミスが1つ取り消される
7. 1ステージ10問。ミスの数で ★1〜3
8. ワールドの最後はボス戦。石・炎・ビームをよけ、最後は突撃してくるボスを踏みつけて倒す
9. 分からないときは、答えのボタンのすぐ上にいる**ペットのボタン**を押す。ヒントが出て、
   そのあいだペットが敵を押しとどめてくれる（画面のペットを直接さわってもいい）。
   ボタンはいつも出ていて、何回でも押せる（回数に限りがあるのは、いちばん最後のボスだけ）
10. リザルトでコインの内訳が出る。**つづける**で次のステージへ、**スタートへ**でいつでも最初の画面に戻れる

ホームからは、マップとは別に3つ入れます。

- **きょうの 5もん** — 苦手な式から5問。1日1回、＋60コイン
- **にがて たいじ** — 何度でも挑める。にがてな式だけが敵になって立っていて、
  時間制限なしで、ビームを撃って倒す
- **ミニゲーム** — 走らない れんしゅう場。3つ（[ミニゲーム](#ミニゲーム)）

## 設計の要点

この3つは、遊びやすさと学習効果を両立させるための意図的な割り切りです。

| | 決めたこと | 理由 |
|---|---|---|
| タイミング | ジャンプの当て判定をしない | 正解した瞬間に障害物のほうが加速して足元を通る。腕前ではなく計算だけで越えられる |
| 制限時間 | タイマーを出さない | 近づいてくる障害物そのものが残り時間。数字のカウントダウンより圧が弱い |
| 失敗 | 通常ステージはゲームオーバーにしない | ぶつかってもコインを数枚落として先へ進む。ステージは必ず最後まで走り切れる |
| 失敗 | ボスだけは1ミスで終わり | 「いつでも安全」だけだと緊張がどこにも生まれない。負けても失うのは★だけで、コインもペットも図鑑も残る |

ほかに実装済みのもの:

- **ワールドはつまずき順に区切る** — W3「10の合成」と W5「繰り上がり」を独立させ、そこだけ繰り返し遊べる
- **1ステージ＝公文のプリント1枚** — ワールドの中の8面は、それぞれ名前と専用の問題を持つ
  小ステップ（「＋2」「9に たす」「いれかえ」「しあげ」）。8面が同じ問題プールから
  引くだけだと、たす数を1つずつ上げていく段階が作れない。マップのマスに名前が出る
- **誤答は実際のまちがいから作る** — ±1（数えまちがい）、繰り上げ忘れ、引いた答え。ランダムな数字は使わない
- **正解の「順位」を先に決める** — 正解が下から何番目になるかを毎回一様ランダムに引き、
  その形になるように誤答を選ぶ。位置も3連続で同じにならないようにする
- **「10 の合成」は空欄をたす数にする** — `7 + ? = 10`。答えが必ず 10 になる形だと、
  式を読まずに 10 を押すだけで通れてしまう
- **「おぼえた」は 4回きれいに正解して初めて** — 速く答えたら +2、では 3択のまぐれ
  当たり2回で図鑑が光ってしまう。上げ幅は必ず +1、まちがえたら −2
- **ボスは★の合計で開く** — 当てずっぽうで通過し続けると★1しか集まらず、ボスに届かない。
  前のステージをやり直せばよい
- **いま押すところは色で分ける** — 道のうえで、いま挑む1マスだけをオレンジで光らせ
  「いま ここ」の札を付ける。クリア済みはせかいの色、まだのところは灰色と 🔒。
  開いたときに、そのマスが画面のまんなかに来るところまでスクロールする
- **「いま どこ」は3か所で同じ絵にする** — ホームの「つぎは 1-4」、みちの「いま ここ」、
  リザルト左の縮小マップ。10問ごとに画面がリザルトへ切りかわると、それまで走っていた
  場所が見えなくなる。同じマスの並びをリザルトにも出して、指させるようにしてある
- **間違えた式は必ず戻ってくる** — 2問後と5問後に再出題。式ごとに習熟度を持ち、未習得の式を優先して出す
- **時間切れは答えを見せてから進む** — ここで正解を教えるのが一番効く
- **マップは「せかい ぜんぶ」→「その せかいの みち」の2段** — 8つの世界が
  何面ずつあり、いまどこまで来たかを一覧で見せてから、選んだ世界の中を
  ぐねぐねした一本道で見せる。道の先には次の世界が待っていることも書いてある
- **ヒントは「10マス」の絵で見せる** — 5歳が一人でも読めるように、式ではなく玉の数で見せる。
  `3+4` は 1枠に色ちがいで、`10と3` は満杯の枠＋バラ、`7+?=10` は空きマスが点滅、
  繰り上がりは 2枠のあいだを玉が移る。2けたは 10 のたばを並べる
- **かならず大きいほうから数える** — `4 + 9` は「9 に 1 を あげて 10、のこり 3」。
  以前は起点を `a` に決め打ちしていたので「4 に 6 を あげて 10」と出ており、
  子どもが実際にやっている数えかたと逆向きだった
- **自動では出しません。呼ばれたときだけ出します** — こちらから勝手に出すのはやめました。
  出るころあいを待つほうが得な場面ができてしまい、待っているだけの時間が生まれていたからです。
  いまは、必要だと思った本人がボタンを押したときにだけ出ます。ボタンは問題が出た瞬間から
  押せる状態で、いつも同じ場所に出ています（「にがて たいじ」も同じ）
- **絵の下には「だから…？」を置く** — 以前は「わかった！」ボタンを置いていましたが、
  押して閉じるだけのボタンでした。いまは `9 + 4` なら「10 と のこり 3 だから…？」のように、
  答えの一歩手前で止めた一文を出します。絵から答えまでを自分でつなぐところを残すためです
  （文言は `tenframe.ts` の `nudge`）。ヒントは、答えたところで自動的に閉じます。
  さくらんぼ（記号）は 1けたどうしの繰り上がりのときに、10マスの絵の横に並べて出します
  （画面が広いときだけ）。繰り上がらない式に出すと、元の式より難しい分け方
  （34 + 31 で「31 を 6 と 25」）になってしまうので出しません。
  さくらんぼの絵は **ミニゲーム「さくらんぼ わけ」と同じもの**（`cherryArt`）で、
  10マスの絵と色の約束もそろえてあります（きいろ＝10へわたす玉、みどり＝のこる玉）
- **「◯◯が おさえてる！」は、押したその瞬間に出す** — 帯（バナー）の持ち時間を
  `update()` の中だけで減らしていたので、**ヒントで世界を止めているあいだは時間が進まず**、
  答えて動きだしてから帯が出ていました。見せるためだけの持ち時間（帯・画面のゆれ・光り・掛け声）は
  `tickEffects()` にまとめて、止めているあいだも進めています
- **ヒントのボタンは、答えのボタンのすぐ上に置く** — 以前は画面のいちばん上のすみにあり、
  親指が届きませんでした。いちばん助けが要る子ほど押せない場所にあったので、
  答えのボタンの真上（ペットの顔と体力ゲージが並んだ帯）に移してあります。
  **画面の中のペットを直接さわっても**同じように出ます
- **押すとペットが敵を押しとどめる** — そのあいだ**世界が止まります**（絵だけ動く）。
  何秒でも考えていい。★・コイン・ずかんには一切ひびきません。
  止まっているあいだも、主人公は ？ を浮かべて考えていて、相手はじりじり押し返してきます。
  全部が凍っていると、押しとどめていること自体が画面から読めなかったためです
- **回数に限りがあるのは、いちばん最後のボスだけ** — さいごのワールド（そらの ちょうじょう）の
  ボス面だけ、押せる回数を数えます（`FINAL_BOSS_HINTS`＝ペットなしで2回、レアなペットを
  連れていると増える）。ボタンのゲージがそのままペットの体力で、0 になると 💤 を出して
  うしろへ歩いていき、その挑戦のあいだはヒントも「せなかに乗せる」も使えません。
  「あと2回」と数字で言われても、数の大きさがまだ分からない年齢には届かない。
  ペットが疲れて消えるほうが、押す前に一度考える理由になります。
  ほかの面ではゲージも「あと○かい」も出しません（数えるものが無いのにゲージだけ出ていると、
  押すのをためらうため）。分からないまま時間切れになるより、絵を見て
  「なぜそうなるか」を通ったほうが次につながる、という判断です

### いま何問目かの ピップ列

HUD の左にある小さな粒（`.pip`）が、いま何問目か・どれを当てたか・どれを外したかです。
色は 緑（正解）／赤（まちがい）／白（まだ）。ここが2つの理由で**色が付かないことが
ありました**。どちらも CSS の詳細度です。

| 症状 | 原因 | 直しかた |
| --- | --- | --- |
| **暗いステージ（夜・ゆうやけ・ボス）では、緑も赤も一度も出ない** | `.screen-play.dark .pip`（クラス3つ）が `.pip.done` / `.pip.miss`（クラス2つ）より強く、下じきの白で毎回 上書きしていた | 下じきの色だけを `--pip-bg` で差しかえる。`background` を直に書かない |
| **リベンジのぶんの粒は、明るいステージでも 緑にも赤にもならない** | `.pip.rev` が `.pip.done` と同じ詳細度で、**あと**に書かれていた | 同じく `--pip-bg` を差しかえるだけにする |

見た目のほうも直しています。以前は `.pips` が `overflow: hidden` で、
`.pip` が下限なしに縮む指定だったので、**れんぞく表示とコインの桁が増えると
列そのものが 0 幅まで潰れて消えて**いました。いまは下限（6px）を持たせ、
入りきらないときは折り返して 10個ぜんぶ必ず出します。あわせて
ステージ名は3倍の速さで幅を譲り（`きょうの 5もん` → `きょう…`）、
スマホの幅では「れんぞく」の字を落として `×7` だけにします。
  ペットが疲れて消えるほうが、押す前に一度考える理由になります。
  ほかの面ではゲージも「あと○かい」も出しません（数えるものが無いのにゲージだけ出ていると、
  押すのをためらうため）。分からないまま時間切れになるより、絵を見て
  「なぜそうなるか」を通ったほうが次につながる、という判断です

## ボス戦

ワールドの最後の1面だけ、ルールが変わります。ここが「本気を出す場所」です。

| | |
|---|---|
| 問題数 | 10問（通常ステージと同じ長さ。1ミスで終わるので長くしない） |
| 失敗 | **まちがえたら、その場で負け**。★は付かず、そこまでのコインだけ残る |
| 攻撃 | ボスが右に立ち、**石・炎・ビーム**を撃ってくる。正解＝跳んでよける |
| よけたとき | 白い輪・火花・掛け声（ナイス！／かわした！…）。体力バーが1目盛り減る |
| 終盤 | 最後の4問は攻撃が **1割はやい**。入る前に「◯◯が ほんきだ！」と知らせる |
| とどめ | 最後の1問はボスが**突撃**してくる。正解すると高く跳んで**踏みつけて倒す** |

でんせつのペットの「せなかに乗せる」だけは、ボス戦でも1回だけ効きます。
ただし効くのは**時間切れ**のときだけで、まちがえたときは助けが入らずその場で負けです。

ボスの見た目と攻撃は、ワールドが進むほど強くなります。

| ワールド | ボス | つの | ふえるもの | 攻撃 |
|---|---|---|---|---|
| 1〜2 | ドドン / ヒュウガ | 2本 | — | 石 |
| 3〜4 | ゴーレム / テンジュウ | 2本 | つめ・腹の鎧 | 石・炎 |
| 5〜6 | ヤマオニ / ナミロウ | 4本 | 3つ目・光る目・はね | 石・炎・ビーム |
| 7〜8 | アラシオン / ソラガミ | 4本 | オーラ・キバ4本 | ビーム中心。攻撃そのものも大きくなる |

負けたときのリザルトは「やられた…」になり、「もういちど」が主役になります。
先へ進む導線はそこでは出しません。

## にがて たいじ

「きょうの 5もん」は1日1回で終わってしまうので、**いつでも挑めて、苦手だけを相手にする場**を
もう1つ置いています。ホームの2枚目のカードから入ります。

走るステージとは、あえて全部ルールを変えてあります。

| | 走るステージ | にがて たいじ |
|---|---|---|
| 出る式 | そのステージの小ステップ | **にがてと記録された式だけ**（2回以上まちがえ、まだおぼえていない） |
| 敵 | 近づいてくる | **その場に立って動かない** |
| 時間 | 障害物が届いたら時間切れ | **時間切れなし**。何分かけてもいい |
| ヒント | ボタンを押したときだけ。世界が止まる | ボタンを押したときだけ。**止めるものが無いので、そのまま出る** |
| まちがえたとき | コインを落とす | 何も減らない。正解するまで何度でも押せる |
| 倒しかた | 跳んでよける | **こちらからビームを撃つ**（ため → 発射 → はじける） |

相手は最大5ひき。倒すたびに画面が光って粒が散り、「たおした！」と出ます。
やりきると ＋30コイン。★もマップの進みも動きません（`saveStars: false`）。

にがてが1ひきもいない日は、カードそのものが押せません（「にがては いないよ！」）。
倒した式は正解のたびに習熟度が上がり、やがて「にがて」から外れるので、
ここを回してコインを稼ぎ続けることはできません。

**急かさない設計です。** 時間制限も、失敗のペナルティも、持続音もありません。
苦手な式は、追われながらでは思い出せない。立ち止まって、ヒントを見て、
自分の手で倒して終わる、という形にしてあります。

## ミニゲーム

本編はどこも「式を読む → 3〜4つの答えから選ぶ → 時間内に跳ぶ」の一本で、**手ざわりが
同じものしかありません**。飽きたときの逃げ場が、走るのをやめること以外に無い。
そこで、走らない れんしゅう場を3つ置いています（ホームの「ミニゲーム」から）。

つまずきは1か所ではなく、下から積み上がっています。3つはその層に1つずつ当てています。

| ゲーム | 何を鍛えるか | 中身 | ひらく条件 |
|---|---|---|---|
| **いくつ？** | 数のかたまりを ぱっと見る（W1〜W2 の下地） | 10マスに玉が 1.5秒だけ出て、消えたあと いくつだったかを答える。1〜5 / 1〜10 / 10より大きい | いつでも（10より大きいは W4 から） |
| **ペアあわせ** | 10 の合成（**W3 のつまずき**、繰り上がりの前提） | 場の数札から、たして きりのいい数になる2枚を探す。5 / 10 / 20 | いつでも（20 は W6 から） |
| **さくらんぼ わけ** | 繰り上がりの分解（**W5 のつまずき**） | `8 + 5` を「8 は あと いくつで 10?」→「5 を 2 と いくつ?」→「10 と 3 で?」の3手に割る。出る式は**にがてな順** | W5 から |

どれも **時間切れがありません**。まちがえても、その場で絵を見て、もう一度押すだけです。

### 記録は動かさない

**ミニゲームの正解・不正解は、習熟度にも★にも図鑑にも反映しません。** 出るのはコインだけです。

ペアあわせは手あたりしだいに押してもそのうち当たるし、さくらんぼは まちがえても
やり直せる。どちらも「おぼえたか」の証拠にはなりません。ここを記録に混ぜると、
図鑑の「おぼえた」と 親の画面の数字が、当てずっぽうで埋まるようになります。
記録を動かすのは本編（走るステージ）だけ、という線はここでも引いてあります。
逆に、**出す式を選ぶときは記録を読みます**（さくらんぼは にがてな式から先に出す）。

### さくらんぼ わけは、絵を出しっぱなしにする

以前は絵を「ヒントを みる」ボタンの奥に置いていました。まだ字の読めない子は
最後までそのボタンを押さず、記号（さくらんぼ）だけを見て当てずっぽうを続けます。
いまは **盤面そのものが絵**です。ボタンはありません。

絵は2段になっています。

- 上 … **さくらんぼ**（`tenframe.ts` の `cherryArt`）。式ごと1枚にしてあり、
  「8 の箱」＋「分ける数 3」から枝が2本おりる形。まだ答えていないほうは点線の `?`、
  分かったほうは色がついて、**下に玉が数のぶんだけ並ぶ**（数字が量と結びついていない子でも数えられる）。
  わたす数が決まると **矢印が箱に向かって出て**、最後の手で箱が `10` に変わります
- 下 … いまの手に合う **10マスの絵**

色の約束は10マスの絵とそろえてあります。**きいろ＝10へわたす玉、みどり＝のこる玉**。
2つの絵が同じ話をしていることが、色だけで分かるようにするためです。

**それでも答えは言いません。**手ごとに、聞いていることの一歩手前で止めた絵にしてあります。

| 手 | 聞くこと | 出す絵 |
|---|---|---|
| 1 | 8 は あと いくつで 10? | 10マスに玉8こ。**空きマスを数えれば 2** |
| 2 | 5 を 2 と いくつに わける? | **5マスだけの列**（2マス色つき・3マス空き） |
| 3 | 10 と 3 で? | くりあがりの絵（答えの 13 は書いていない） |

2手めに 10マスの枠を使わないのは、聞いていない残り5マスまで空きマスとして並び、
「あと いくつ」を数えるつもりの子が 5 を数えてしまうからです（`splitArt`）。
まちがえたときは、絵のほうが1回ゆれます。ことばで答えは足しません。

### コインは1日1回だけ多い

やりきると **1日1回めは ＋40、2回めからは ＋10**。まちがえずに通すと ＋15 の上乗せ。

ここを一定にすると、いちばん短いミニゲームを回すのがコインの最適解になり、
走る理由が消えます（★3 のステージ周回に `REPLAY_RATE` を置いたのと同じ理由）。
それでも 2回め以降を 0 にはしません。0 だと「もう やってもむだ」になり、
れんしゅう場としての意味まで消えます。

遊んだ時間は**「1日にあそべる時間」に数えます**（上限に達した日は、本編と一緒に閉じます）。
ここだけ上限の外に置くと、上限をつけた家庭でミニゲームだけ無限に遊べてしまいます。

## たしざん図鑑

1〜9 どうしの **81通り**を表にして、おぼえた式のマスが光ります。勉強の進みが

### タイトルは、開いた瞬間に動いている

最初に見る画面が静止画だと、それだけで「まだ始まっていない」ことになります。
ロゴとボタンだけだった画面に、**レイアウトに一切かかわらない飾りの層**を1枚足しました
（`.sky-deco` — すべて絶対配置・`pointer-events: none` なので、行が増えても
ボタンの位置は動かず、押しまちがえも起きません）。

- おひさまが ゆっくり息をして、くもが3つ ちがう速さで流れ、とりが2羽 横切る
- ロゴの左右で ★ が回り、空に きらきらが またたく
- 「あそぶ」に 光が すっと流れる（押すところが ひと目で分かる）
- 草の上では **ぴょんぴょん広場** のなかまが跳ねていて、さわると反応する（前からある）
- **いまの ぶき**の帯（絵＋名前＋「さいごの 1もんで ◯◯」）。押すと きせかえの ぶきタブへ

飾りは `prefers-reduced-motion` で全部止まります。

### 横向きは2列にする

ホームは行が多い（ロゴ・カード5枚・ボタン・広場）ので、1列のまま縦に積むと
**iPad を横にしただけでスクロールが要ります**。遊ぶ前にスクロールさせるのは、
「開いた瞬間に全部見える」を捨てるのと同じです。

横向きで幅が 40rem 以上あるときは、2列に分けます（`@media (orientation: landscape)`）。

| 左の列 | 右の列 |
| --- | --- |
| ロゴ・**あそぶ**・きせかえ／ペット／ずかん・ぴょんぴょん広場 | きょうの5もん・にがて たいじ／ミニゲーム・ずかん・ペット・いまの ぶき |

iPad（1180×820 / 1133×744 / 1024×768）と スマホの横持ち（852×393 / 667×375）で、
**どれもスクロールなしに収まる**ところまで詰めてあります。スマホの横持ちだけは
行のあいだと、横に並ぶ2枚のカードの絵をさらに落とします（字のほうを残す）。

このメディアクエリは **ホームの節より後ろに置くこと**。前に置くと、あとから来る
`.home` や `#home-char` の指定に負けて、行の詰めが効きません。

## フィニッシュ（最後までやりきる理由）

5歳は面の途中で手を止めます。ステージを開いて3問だけ答えて戻る、という日が普通にあります。
そこに効くのは「途中でやめると損だ」ではなく、**「最後まで行くと、そこにだけ在るものがある」**
のほうです。

**ステージ・きょうの5もん・にがて たいじ の さいごの1問**を当てたときだけ、
えらんだ **ぶき** で大げさに とどめを刺します（`src/weapons.ts`）。

- 走るのも景色の流れも止まって、相手と向かい合う
- ためる → 撃つ／振りおろす → はじける、の順に 2.8秒
- 倒したところに **＋20コイン**（リザルトに「◯◯ フィニッシュ」の行が出る）
- ボスは突撃を踏みつけるのが とどめなので、踏んだ瞬間に同じ ぶきの光が出て同じだけ払う

### 「何で倒したのか」を見せる

最初の作りでは、フィニッシュのあいだ画面をまたぐ帯（「フィニッシュ！ ブーメランエッジ」）を
出していました。これが**いちばん見せたいものの前に出ていました** — 帯は canvas の上端から
40*s の高さを横いっぱいに塗るので、まほうじん（つえ・ステッキ・ロッド）と
振りかぶったハンマーは、まるごと帯のうしろでした。字は読めるが、絵は見えない。

いまは帯を使わず、次の4つで見せます。

| | やること | 効き |
| --- | --- | --- |
| **暗転** | 景色を描いたあと、**主人公と相手を描く前に**相手を中心とした明かりを敷く（`drawFinishDim`） | 暗くなるのは うしろの世界だけ。2人と ぶきの光は明るいまま残るので、どこを見ればいいかが 字なしで決まる |
| **タメ** | ためを 0.62 → **0.88秒**。撃つ直前に体をぐっと後ろへ引き、相手のまわりで照準の輪がしぼむ（`drawLockOn`） | 「つぎの瞬間、ここに来る」が先に分かるので、当たったところを見のがさない |
| **ヒットストップ** | 当たった瞬間、**0.14秒だけ世界を止める**（光り・ゆれ・カットインだけ進む） | 当たったコマそのものが目に残る |
| **カットイン** | ぶきの名まえは 画面の**左上の小さな板**で言い、**放つ前に引っこむ**（`drawFinishCutIn`） | とどめの瞬間には、画面に字がひとつも無い |

まほうじんと 振りかぶったハンマーの高さ（`skyY`）には下限を入れて、カットインの板より
必ず下に出るようにしてあります。ここを浅くすると、また板のうしろに隠れます。

`showBanner()` は「いま見せたい絵がない」ときだけに使うもので、とどめの演出には使いません。

置きかたも、見えるところにそろえてあります。

- **ホーム** に「いまの ぶき」の帯。押すと きせかえの ぶきタブへ直行する
- **最後の1問が出た瞬間**の帯が「ラスト 1もん！ ひかりの けん」。当てれば これが出る、と先に言う
- **ポーズ画面**に「さいごの 1もんまで いくと、◯◯ で フィニッシュ！」。やめる前にもう一度言う

まちがえて時間切れになった場合は出ません（コインも付きません）。
出すのは「当てた人」にだけで、そこが やりきる理由になります。

## コインの使いみち

コインは 1ステージで 30〜100枚たまります（内訳は「[コイン](#コイン)」）。

| 使いみち | 値段 | 性質 |
|---|---|---|
| きせかえの **ガチャ** | 90 | **キャラ／ぶき／ぼうし／アクセ／いろ から種類をえらんで**1回まわす。その種類の未所持から1つ出る |
| ペットの **たまご** | 120 | ふつう 66% / レア 26% / スーパーレア 7% / でんせつ 1% |
| ペットの **キラたまご** | 200 | ふつう 25% / レア 40% / スーパーレア 27% / でんせつ 8% |
| ずかんの **ごほうび** | （もらうほう） | カードを9まいおぼえるごとに ＋30。使いみちではなく、図鑑を開かせるための出口 |

### きせかえで「すること」は1つだけ

以前は たまご（ランダム 90）・ねらい買い（210）・いろの直接買い（75〜240）の
**3通り**があり、マスごとに ちがう値段が並んでいました。5歳には
「なぜ同じ ぼうしが たまごなら 90 で、名前を押すと 210 なのか」が読めず、
きせかえの画面が値札の一覧になっていました。

いまは **「どの種類を増やすか えらぶ → ガチャを1回まわす」** だけです。

- 種類（キャラ・ぶき・ぼうし・アクセ・いろ）は5つとも画面に出ていて、押すとガチャの
  ボタンの文字が「ぼうしの ガチャ」に変わる。**選んだものが、そのまま次に出るもの**
- 値段はどの種類でも同じ 90 で、**出るのはガチャのボタン1か所だけ**。マスに値札は付けない
  （種類ごとに値段を変えると「いろは安いから いろを回す」という損得の計算が始まる）
- **まだ持っていないものも、絵と名前は出します。**伏せると「なにが欲しいか」を決められず、
  コインを貯める目標になりません。未所持のマスには `？` の目じるしだけ付けて、
  押すと「〇〇は ガチャで あたるよ！」と言い、ガチャのボタンが1回はねます

いろをガチャに入れたので、`にじいろ`・`きんいろ` を狙い撃ちで買うことはできなくなりました。
そのかわり、**どの種類も同じ1回**で増えます。手に入れかたを1つにそろえるほうを取っています。

### 使いみちは、稼いだその場に置く

貯まっても「それで何ができるのか」が画面のどこにも出ていないと、コインはただの数字に
なります。リザルトのコインの下に、いま何ができるかを1枚だけ出します。

- 届いているなら **「ペットの たまごが われる！」／「きせかえの ガチャが まわせる！」**
  （押すと ぼくじょう／きせかえへ）
- 足りないなら **「あと 37 コインで たまご」**（きせかえなら「…で ガチャ」）と棒グラフ。
  走る前の枚数から伸びるので、「さっきより近づいた」が目で分かる
- ペットのほうを先に見るのは、子どもが割りたがるのがペットのたまごだから

そこから入った きせかえ／ぼくじょうには **「つづきを あそぶ」** が下に出て、
← はリザルトへ戻ります。**あそぶ → まわす／割る → 続きをあそぶ** が
一本の道になり、ホームまで戻らないと使えない状態をなくしてあります。
ホームの「きせかえ」には まわせるときだけ 🎁、「ペット」には割れるときだけ 🥚 が付きます。

## ペットと ぼくじょう

ひよこ・かえる・スライム・あおむし……から ドラゴン・ペガサス・ユニコーン・
フェニックスまで **30種**。たまごから生まれた子は、そのままステージへ
連れて歩けます（走っているあいだ、少し後ろをついてくる）。

| レア度 | 数 | はたらき |
|---|---|---|
| ふつう | 12 | いっしょに走る（見た目だけ） |
| レア | 9 | 障害物が 8% ゆっくり ＋ さいごのボスで ヒントを**1回**ふやす |
| スーパーレア | 5 | 14% ゆっくり ＋ さいごのボスで ヒントを**2回** |
| でんせつ | 4 | 20% ゆっくり ＋ さいごのボスで ヒントを**4回** ＋ **1ステージに1回だけ、時間切れの障害物をせなかに乗せて越えてくれる** |

ヒントに回数があるのは**いちばん最後のボスだけ**なので、ペットの「ヒントを増やす」力が
効くのもそこだけです。そこでもペットがいなくて**2回**は押せます（`FINAL_BOSS_HINTS`）。
ここを「ペットがいないと0回」にすると、引きの悪さがそのまま難しさになってしまうので、
ペットは基本回数に**足す**だけです。

その回数は、プレイ中は**ペットの体力ゲージ**として見えます。ヒントを1回呼ぶたびに減り、
空になるとペットは 💤 を出して画面から歩き去ります。その挑戦のあいだは
ヒントも「せなかに乗せる」も使えません（挑みなおせば戻ってきます）。

同じ子がもう一度出たら **なかよし度**が上がり（最大♥5）、1つにつき効果が +2%
（ヒントは♥2つで1回）。
コインも 24枚もどります。30種そろったあとも、たまごを割る意味が残ります。

**助けてもらっても、まちがいの記録は変わりません。** せなかに乗せてもらった問題は
ミスとして数え、習熟度も下げたうえで、同じ問題にもう一度だけ挑ませます。
ここを甘くすると、レアを引けた子だけ★と図鑑が伸び、「引きの良さ」が
学習の記録に化けてしまう。助けるのは気持ちの面（つまずいた直後に立て直せる）だけです。
効果はどれも「やさしくなる」方向で、引けないと難しくなる要素はありません。

**ぼくじょう**は、持っている子が全員そこを歩き回る画面です。一覧の表だけでは
数が増えても嬉しくないので、増えるほど画面がにぎやかになるようにしてあります。
つれて歩く子は足もとの輪とハートで分かります。

**さわると返してくれる。** 牧場の子をタップすると、鳴き声・大ジャンプ・くるっと回る・
ハート・おどり のどれかを返し、そのあと歩く向きも変わります（何度さわっても
同じにならない）。下の行にはその子のひとことが出ます。タイトルの草の上も同じで、
じぶんの子と なかまが跳ねまわっていて、さわると反応します。見ているだけの画面と
さわれる画面では、居つく時間がまるで違います。

### 景色と障害物

「ずっと同じ野原」は 3ステージで飽きます。かといってワールドごとに絵を1枚ずつ用意しても
8種類しか作れないので、景色を 2軸に分けて掛け合わせています（`src/theme.ts`）。

| 軸 | 決めるもの | 数 |
|---|---|---|
| ワールド | 地面・丘・木や建物・天気（花びら／落ち葉／雪／泡／雨／ホタル／星）・出る障害物 | 8 |
| 時間帯 | 空の色・太陽／月・星・全体にかける色 | 6（朝・昼・夕・夜・ボス・にがて たいじ） |

40通りになるので、隣り合うステージが同じ絵になりません。時間帯は**ステージ番号から決まる**ので、
同じステージはいつ遊んでも同じ景色です（日によって変わると「あのステージ」として覚えられない）。
みちのマスにも時間帯のしるしを出して、遊ぶ前に「次はちがう場所だ」と分かるようにしています。

障害物は 12種類（岩・くさむら・スライム・まるた・とり・きのこ・おばけ・パイロン・はこ・
ゆきだるま・クリスタル・かに）で、**1問ごとに引き直し**ます。同じものは2回続けて出しません。
動きも種類ごとに違います（スライムはぷるぷる、まるたは転がる、とりは羽ばたく、おばけは浮かぶ）。
当たり判定はどれも同じで、違うのは見た目だけです。

これとは別に **にがて** の相手がいます。2回以上まちがえていて、まだおぼえていない式のときだけ
景色を無視して出てきます（つの・とげ・「にがて」のふきだし）。式の上にも「にがて」の札が出て、
初回で正解すると「にがてを たおした！」とコインが上乗せされます。図鑑の同じ式のマスも赤くなるので、
**たおすべき相手が、プレイ中と図鑑の両方で同じ姿として見える**ようにしています。
これまで `FactStat.miss` は親の画面でしか使っていませんでしたが、同じデータの子ども向けの見せ方です。

**よけるものは、色ではなく形で浮かせます。** ボス戦の空はどれも暗い紫〜赤で、丘と草も
その色に 34% 寄せて塗るため、灰茶色の石はちょうどその明るさの帯に入って輪郭が消えていました。
石とビームには「うしろの暗いにじみ・濃いふちどり・上下のグラデーション」を重ねて、
背景が何色でも縁が切れるようにしてあります。よけられないと理不尽になる絵は、
背景に依存する手がかり（色の違い）だけに任せないという方針です。

| にがてを初回で正解（げきは） | ＋3 |
| ノーミス（★3） | ＋30 |
| **フィニッシュ**（さいごの1問を ぶきで しとめる） | ＋20 |
| ボス | ＋60 |
| きょうの5もん | ＋60 |
| にがて たいじ をやりきる | ＋30 |
| はじめてクリア | ＋20（★を保存するステージだけ） |
| はじめて★3 | ＋40（同上） |
| 時間切れでぶつかる | −3（その走りで稼いだぶんが上限。マイナスにはならない） |

上の枚数には、さらに**2つの倍率**が掛かります。

| 倍率 | 値 | なぜ |
|---|---|---|
| ワールド（`World.coinRate`） | W1 0.6 → W8 1.8 | 奥ほど1問が重い |
| ★3を取り終えた面の再挑戦 | ×0.4 | 周回だけ割に合わなくする |

これが無かったころは全ワールド・全周回で同額だったので、
**いちばん速く終わるいちばん易しい面を回すのが数え上げで最適**でした。
実測（Chromium）で W1-1 は 初クリア＋86 / ★3周回＋23、
「じゅうのまち」の周回は 78 → 24 になり、先の面を1つ進めるほうが数倍得になります。
画面には「減った」とは出さず、初回の上乗せ（「はじめて クリア＆★3！」）としてだけ見せます。
練習そのものは何回でもできます。

たまごの値段も同じ倍率（きせかえ 90／ペット 120・200、いろ 75）にしてあるので、
手に入るきせかえの数は変わりません。
以前の版で貯めたコインは、読みこむときに3倍して持ち越します（`save.econ`）。

### きろく（セーブデータ）

きろくは 3枠です。きょうだいで1台を使いまわしても、星もコインも図鑑も混ざりません。
ホームの名前をタップすると選びなおせます。2枠以上つかっていると、起動時にまず
「だれの ぼうけん？」から始まります。消すときは確認を1枚はさみます。

## おうちのかた（親モード）

### せっていは、子どもの導線の外に置く

以前は ホームに「きせかえ／ペット／ずかん／せってい」が横に並んでいて、
**せっていだけ子どもの用が無いのに、同じ大きさで同じ場所にありました。**
いまは ホームの並びから外して、画面の**右上のすみに小さい歯車**（`.gear`）を置いてあります。

すみに置くだけでは足りません（遊んでいる指は端まで来ます）。
**ひと押しでは開かず、0.8秒ながおしで開きます**。押しているあいだ歯車がゆっくり回るので、
おとなには「開きかけている」ことが見えます。短く押したときは
「ながおしで ひらきます」とだけ出して、責めずに開きかたを教えます
（キーボードの Enter／Space では、そのまま開きます。使うのはおとなだけなので）。

せってい → 「おうちのかたへ」から入ります。関門は PIN ではなく **2けたの足し算**です。
PIN は必ず忘れますが、`47 + 68` は大人なら暗算でき、6歳には難しい。目的は
子どもがうっかり入らないことで、厳密なロックではありません。

- **つまずいている計算 トップ5** — まちがえた割合の高い順に、回数と平均解答時間つき。
  紙のドリルで補う場所がそのまま決まります
- **1日にあそべる時間** — 上限に達しても途中で止めません。ステージの切れ目で
  「きょうの ぼうけんは ここまで」になり、図鑑・きせかえ・ぼくじょうは見られるままにしてあります
- **ゆっくりモード** — 障害物の速度を 60% に
- **セーブデータの持ち出し／読みこみ** — 機種変更のとき用（3枠ぶんまとめて移ります）
- **さいしょから やりなおす** — 取り返しがつかないので、子どもが開ける設定画面ではなく
  この関門の内側に置いています

## 出題エンジンの検証

`tools/verify-questions.mjs` で、出題ロジックだけを取り出して統計的に確かめられます。

```bash
npm run verify
```

ワールド全体と**小ステップごと**に問題を引いて、次を見ます。

| | 見るもの |
|---|---|
| A | 正解の順位が一様か（＝計算せずに位置や大きさで当てられないか） |
| B | 当てずっぽうだけで「おぼえた」に届いてしまわないか |
| C | 選択肢の数・重複・正解の有無・0以下 |
| D | さくらんぼ分解が繰り上がる式にだけ出て、**大きいほうが起点**になっているか |
| E | 面数が8のままか（★の保存キーがずれない）・**ずかんの81マスがちょうど埋まるか** |
| F | ヒントの絵。枠が3つを超えないか、「だから…？」の一文があるか、絵の出ない式がどこにどれだけあるか |

A の上限は、以前は世界ごとの表に手で書いていました。中身を入れかえると黙ってずれるので、
いまは `questions.ts` の誤答プールを直接読んで解析的に出しています
（コメントにある W1 36.7% / W3 40.7% をそのまま再現します）。
小ステップは問題数が少ないぶん偏りやすいので、ここが本番です。

E のずかん被覆の検査は、これまでどこにもありませんでした。

## iPhone / iPad で試す

### 1. 単一ファイルを送る（いちばん手軽）

```bash
npm install
npm run build:single      # dist/tashizan-jump.html （約 50KB の1枚）
```

できた `tashizan-jump.html` を AirDrop かメールで iPhone に送り、Safari で開けば
そのまま遊べます。サーバーもネットも不要です。
（この形ではホーム画面追加とオフラインキャッシュは使えません）

### 2. 同じ Wi-Fi の PC から配信する（開発中はこれ）

```bash
npm run dev
```

ターミナルに出る `Network: http://192.168.x.x:5173/` を iPhone の Safari で開きます。
コードを直すとその場で反映されるので、子どもの反応を見ながら調整できます。

### 3. GitHub Pages に置く（ホーム画面に入れるならこれ）

既定ブランチに push すると `.github/workflows/pages.yml` が動いて配信されます
（手動で流すこともできます: **Actions → Deploy to GitHub Pages → Run workflow**）。
配信されたら iPhone の Safari で開く → 共有ボタン → **ホーム画面に追加**。

追加したアイコンから起動すると、アドレスバーのない全画面になります。

> Pages で公開したページは誰でも見られる状態になります。

### 最初に一度だけ必要な設定

**Settings → Pages → Source を `GitHub Actions` にしてください。** これは人が
手でやるしかありません。workflow から変えることはできず、`GITHUB_TOKEN` に
`pages:write` を与えても `PUT /repos/{owner}/{repo}/pages` は
`403 Resource not accessible by integration` になります
（`configure-pages` の `enablement` でも直りません。未設定のときに作るだけで、
すでにある設定は変えないため）。

ここが `Deploy from a branch` のままだと、**Actions のデプロイが成功しても
配信には反映されません**。ブランチ側のビルドが生き続け、ビルドしていない
ソースが公開されます。Actions が緑なのにページが直らない、という形になるので
気づきにくい。`Settings → Pages` の表示が `GitHub Actions` になっているか、
実際に配信されている HTML に `assets/index-` が入っているかで確かめられます。

### 配信でハマるところ

このリポジトリは Vite でビルドしてから配る必要があります。`index.html` が
TypeScript の `/src/main.ts` を読みにいくので、**ビルドを挟まない配信経路に
乗ると必ず失敗します**。ブラウザは `.ts` を JavaScript として実行しません。

ビルドを挟まない経路は 2つあり、どちらも「真っ白／動かない」になります。

| やってはいけないこと | 何が起きるか |
| --- | --- |
| **Settings → Pages → Source をブランチにする** | リポジトリ直下がそのまま配信される。`dist/` は Git に入っていないので、配られるのはソースそのもの |
| **Jekyll のワークフローを足す** | `actions/jekyll-build-pages` はリポジトリ直下を配る。上と同じ結果になる |

とくに 2つめは、GitHub の Pages 設定画面が Jekyll のワークフローを勧めてくるため
入りこみやすい。`pages.yml` と両方あると、**同じ push で 2つとも走って先着順で
上書きし合う**（どちらも concurrency group が `pages`、`cancel-in-progress: false`
なので、片方が待ってから後勝ちになる）。成功したり失敗したりする、いちばん
分かりにくい壊れかたをします。

**Pages に配信するワークフローは `pages.yml` ひとつだけにしてください。**

## PWA について

ホーム画面に追加してアプリのように使うために、次の 2つを置いています。

| ファイル | 役割 |
| --- | --- |
| `public/manifest.json` | アプリの名前・アイコン・起動時の見た目 |
| `public/sw.js` | オフライン用の Service Worker |

### オフライン

`sw.js` は install の時点でアプリ一式（HTML / JS / CSS / アイコン / manifest）を
まとめてキャッシュします。「一度読んだものを残す」方式では足りません
——Service Worker は自分を登録したページの読みこみを横取りできないので、
初回訪問ぶんがキャッシュに入らず、その直後に圏外になると起動できなくなります。

ファイル名にはビルドごとのハッシュが付くため、一覧は `vite.config.ts` の
`sw-precache` プラグインがビルド時に `sw.js` へ埋めこみます。キャッシュ名にも
中身のハッシュが入るので、配信するたびに古い版はまとめて捨てられます。

プリキャッシュは `cache.addAll` で丸ごと入れています。1つでも失敗すると
install ごと失敗しますが、それでかまいません。中途半端に入ったまま先に進むと
古いキャッシュを消してしまい、「更新したら圏外で遊べなくなった」が起きます。
install に失敗した新しい Service Worker は破棄され、いま動いている版が残ります。

### 更新

HTML はネットワーク優先、それ以外はキャッシュ優先です。ファイル名にハッシュが
付くので、キャッシュ優先でも古い版を掴み続けることはありません。

更新の確認はアプリ側から明示的に呼んでいます（`src/main.ts`）。画面を開いた
だけでは `sw.js` を取りにいかないことがあり、ホーム画面から起動したアプリには
再読みこみの手段がない（引っぱって更新は `overscroll-behavior: none` で
止めてある）ので、放っておくと古い版のまま何日も動きます。
起動時と、1時間以上あけて前面に戻ってきたときに確認します。

### アイコン

`icons/icon-maskable-512.png` は絵を内側 80% に寄せた maskable 版です。
Android はアイコンを端末ごとの形（丸・角丸・雫）で切り抜くので、フチいっぱいに
描いた絵だと「＋」の先が欠けます。空と地面は切り抜かれる前提でフチまで塗っています。

### iOS 向けにやってあること

- `viewport-fit=cover` + `env(safe-area-inset-*)` でノッチとホームバーを避ける
- `touch-action: manipulation` と `gesturestart` の抑止でダブルタップ拡大を止める
  （`user-scalable=no` は iOS Safari では無視されるため）
- `position: fixed` + `overscroll-behavior: none` で引っぱって更新（バウンス）を止める
- 音は最初のタップで unlock。消音スイッチが ON でも鳴るように
  Safari 16.4+ の `navigator.audioSession.type = 'playback'` を設定
- 低電力モードで 30fps に落ちても速度が変わらないよう、フレーム数ではなく経過時間で動かす
- `devicePixelRatio` は 2 で頭打ち（3倍は塗り面積が 2.25 倍になり発熱する）
